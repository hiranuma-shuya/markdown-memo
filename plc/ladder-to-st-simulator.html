PLC / IEC 61131-3

ラダー→ST 変換のしくみ

ラダーを知らないSEのための、触って分かる解説。左に「動いているラダー」、右に「同じ意味の ST」を並べます。ボタンを押して、1スキャンずつ進めてみてください。

1PLC は「ぐるぐる回る while ループ」

PLC は工場の機械を動かす小さなコンピュータです。中のプログラムは、SE の言葉にするとこれだけです。

while (true) {
  入力を読む();            // センサやボタンの ON/OFF をメモリにコピー
  プログラムを上から下まで実行();
  出力を書く();            // メモリの値をモータやランプに出す
}

この 1 周を スキャン と呼びます。1 周は数ミリ秒。1 秒に何百回も回り続けます。

SCAN 0000

スキャンの流れ

入力メモリ X0 = OFF Y0 ランプ（実際の出力）

ラダー

同じ意味の ST

やってみる: スイッチを押して「1スキャン進める」。①で入力メモリにコピー → ②でラングを評価 → ③でランプに出る、の順に進みます。ランプが変わるのはスキャンの終わりです。

大事なこと。ラダーも ST も、この同じループの中で動きます。ST にしたからイベントドリブンになるわけではないし、軽くなるわけでもありません。言語が違うだけで、実行モデルは同じです。

2ラダーの読み方（SE 向け翻訳）

ラダーは「電気回路図の見た目で書くプログラム言語」です。正式には LD（Ladder Diagram）。左右の縦線が電源のイメージで、横に 1 本ずつ ラング（段） を書きます。左から右に「電気が流れる」と考えて読みます。

部品は 2 種類しかありません。接点（変数を読む）と コイル（変数に代入する）。つなぎ方が AND / OR になります。下の接点はクリックで ON/OFF できます。

つまり 1 ラング = 1 つの bool変数 := 式; です。変数名は X0（入力）、Y0（出力）、M100（内部メモリ）、D100（数値）のように、種類 + 番号で書きます。三菱 PLC の流儀です。

3自己保持 = 「ボタンを離しても覚えている」回路

ラダーで一番大事な基本パターンです。起動ボタンを押すと動き始め、ボタンを離しても動き続け、停止ボタンで止まる。どんな設備にもある動きを、この 1 ラングで作ります。

SCAN 0000

ラダー

そのまま ST に直訳（自動生成）

  1. X0 起動 を押して「1スキャン」→ M100 が ON になる
  2. X0 起動 を離して「1スキャン」→ まだ ON のまま。これが自己保持
  3. X1 停止 を押して「1スキャン」→ OFF になる

SE 的に言うと、自分の出力を自分の入力に戻している 1 ビットのメモリ（SR フリップフロップ）です。右辺の M100 は「前のスキャンで代入した値」を読んでいるので、覚えていられます。

ST への直訳は 1 行。単発の自己保持なら、この 1 行のままで何も困りません。「ST らしく書き直す」必要が出るのは、次の章のように工程が連なるときです。

4工程の鎖 → 「今どこ？」を 1 つの変数にする

機械の動きには順番があります。ラダーでは、自己保持リレーを鎖のようにつないで順番を作ります（工程歩進と呼ばれます）。例として、シリンダでワークを押し出す 3 工程の設備を動かしてみます。

工程やること次へ進む条件
1 前進前進ソレノイド Y0 を ON前進端センサ X2 が ON
2 クランプクランプ Y2 を ONクランプ確認 X4 が ON
3 後退後退ソレノイド Y1 を ON後退端センサ X3 が ON → 待機に戻る

下のラダーは実際に動いています。「▶ 自動」にして起動ボタンを押すと、1 サイクル回ります。右の ST 直訳は、ラダーから機械的に生成したものです。

    ラダー版の出力書き直し版の出力2 つの出力が違うスキャン

    ここが変換の価値の正体です。ラダーには「今、工程 2 にいる」を持っている変数が どこにもありません。M101 / M102 / M103 の ON/OFF の組み合わせを、人がモニタ画面から読み取って初めて分かります。状態が暗黙的に、複数の変数に散らばっているのです。

    書き直し版は、その暗黙の状態を step という名前のついた 1 変数にしました。「ST らしく書き直す」工数の大半は、この掘り起こし（どのビット群が工程を表しているか、どこがインタロックか）に消えます。

    波形のオレンジの目印を見てください。ラダー版と書き直し版は、切り替わりの瞬間に出力が 1 スキャンずれています。ラダーはラングの順番で「工程 1 の OFF が 1 スキャン遅れる」構造なのに対し、CASE 文は同じスキャンで切り替わるからです。

    機械の動き自体は同じ。でも「完全に同じ」とは言えないので、変換後に、同じ入力を流して出力を比べる等価性の検証が要ります。これも工数です。

    5ラングの順番と「1 スキャン遅れ」

    スキャンは上から下に実行されます。だから、ある変数を 書いてから読む と今のスキャンの値、読んでから書く と前のスキャンの値になります。同じ 2 ラングを、順番だけ入れ替えて試してみてください。

    X0 を ON にして「1スキャン」を押すと、Y0 が何スキャン後に ON になるかが出ます。

    ラダーの順番は「タイミング」を決めています。設計者はこの 1 スキャン遅れや、リセット優先 / セット優先の書き方を意図的に使っています。CASE 文にまとめ直すと実行順が変わるので、意図だったのか偶然だったのかを見極めないと、動きが変わります。これが「難しさ」の 2 つ目です。

    なぜ「書き直す」変換は難しいのか

    • 状態が暗黙的に分散している。どのビットの組み合わせが工程を表すのかを見つけ出す作業。機械語を構造化された C に逆コンパイルするときの制御フロー復元と同じ問題。
    • ラングの順番と 1 スキャン遅れに意味がある。まとめ直すとタイミングが変わる。だから等価性検証が要る。
    • 同じ変数への書き込みが散在している。あちこちにある SET / RST を「誰がこの変数を書いている？」と全部集めないと、機構ごとにまとめられない。

    誤解しやすいポイント

    • 1 つの CASE 文になるわけではない。設備には機構がたくさんある。機構ごとに FB に分かれ、それぞれが自分の step を持つ。その上に上位フローがあって、それも step を持つ。階層構造。
    • CASE 文とも限らない。SFC 言語や State パターンでも書ける。本質は「どこにも書かれていない状態を、名前のついた変数にする」こと。
    • 全部が状態機械になるわけでもない。インタロック、非常停止、アラーム検出、手動ジョグは順番を持たない。ST でも単なる代入文のまま、CASE の外に置く。
    • 全ラダーに一律でかける必要はない。価値の高い機構から書き直し、残りは直訳でテキスト管理だけ享受する混ぜ方が現実的。

    ラダーには「今どの工程か」がどこにも書かれていない。
    ST 変換の価値は、それを名前のついた変数にすること。
    その掘り起こしが、工数の正体。 このページのラダーは本物のスキャン順序で評価しています。直訳 ST はラング定義から自動生成、書き直し版は手書きの状態機械を同じ入力で並走させています。
